Automatic Recovery Probe

Gets your files back off the recovered SSD, checks every one and repairs what it can. It never writes to the SSD.

Where your files go

The recovered SSD is read once and never written to. Everything after that works on copies.

    1. 1

      Get ready

      First the program checks this PC and the free tools it uses. Do this while the recovered SSD is not plugged in.

    2. 2

      The rehearsal with SPARE

      Before the recovered SSD goes in, make sure Windows will keep it switched off, so nothing can write to it. You try it out with SPARE: it is empty, so there is nothing to lose.

      1. Keep new disks switched offClick First: make Windows leave new disks switched off.
      2. Plug SPARE in, the same wayExactly as the recovered SSD will be: the same USB case or adapter, the same port and cable.
      3. Let the program check itIn the list of disks, click This is SPARE: check it. You want “SPARE arrived switched off”.
      Why SPARE, and what if it arrives switched on?

      Some USB cases and adapters make Windows switch a disk on anyway, often because Windows remembers the case itself. The recovered SSD in that same case would then arrive switched on too.

      If SPARE arrives switched on, click Switch SPARE off, unplug it, plug it back in exactly the same way and check it again. If it now arrives switched off, so will the recovered SSD. If the program says to stop, don't plug the recovered SSD in that way.

    3. 3

      The folders

      Where the program puts what it makes. It suggests these; change them only if you need to.

      As big as the old drive: on a drive inside this PC with room for it.

      Every file is copied here and checked. REPAIR, where the repairs are made, goes beside it on the same drive.

      On this PC, beside the image.

      If an undamaged copy of a damaged file is found there (or anywhere in WORK), it is restored exactly instead of repaired.

    4. 4

      Start

      Press Start and the program does the rest by itself, stage by stage. It tells you when to plug something in, and stops and says why if any check finds a problem. After a stop, a closed window or a power cut, press Carry on: it picks up where it stopped.

    5. 5

      What is left: the Mac, or a paid tool

      What no free tool could repair is made ready in REPAIR\hand-off: for the Mac, for a paid repair tool, or for the file's own program. When repaired files come back, Bring back puts each one in its place and checks everything again.

      This fills in once Start is done.

    6. 6

      Finalise

      Keeps everything safe, once Start (and any Bring back) is done. Finalise:

      • makes a RECORDS folder beside WORK: the results, the mapfile and the checklists;
      • copies WORK, REPAIR and RECORDS into the second-copy folder, every file keeping its dates;
      • checks both copies, and the image, one last time.

      It leaves Windows' settings as they are: they go back separately, in 7, once every drive is unplugged.

      Run it again twice a year: it checks everything again and names any file that has changed.

    7. 7

      Put Windows back as it was

      To protect the recovered SSD and to work faster, the program changed a few Windows settings. They stay that way until you put them back here, and the button only works once every drive is unplugged: the recovered SSD, the 4 TB SSD and SPARE. That way the recovered SSD can never arrive switched on.

    Loading the checklist…

    These are the program's own steps, one at a time: the same work Start does by itself, and what Start did shows here too. Use them to look at a result in detail. Do a step again from here only if Claude asks you to: Automatic recovery does them all, in the right order, and keeps track of what is done.

    Choose the mapfile in step 2 to see where the old drive was damaged.

    1. 1

      Check the program works on this PC

      The program checks itself on sample files and a small damaged test disk it carries, where every right answer is known. It takes a few seconds and touches nothing of yours.

    2. 2

      Your ddrescue mapfile

      The mapfile is the small file ddrescue wrote while it copied the old drive. It lists every place on the drive it could not read. If there was more than one attempt, choose the last one.

    3. 3

      Connect the recovered SSD, protected

      When a drive is plugged in, Windows starts using it straight away and can write to it on its own. On the only copy of your files that must not happen, so here it arrives switched off and the program marks it read-only. Windows stays set to leave new disks switched off until you put it back yourself (step 9), which works only once every drive is unplugged.

    4. 4

      Make an image of the SSD: a second copy

      The whole SSD is read once, from start to end, into one file on another drive: a complete second copy, checked by reading it back. After that the SSD is not needed any more (it goes back in its drawer), and the next steps read the image instead, as often as needed.

      More about making the image

      If the SSD struggles at a place, the image reads around it carefully, steps over what will not read (and lists it) and goes on, rather than wearing the SSD down there. Stop works at any moment, and starting again carries on where it stopped. The image is about 1,000 GB: choose a folder on a drive formatted NTFS with that much free, such as IMAGE on the PC's own second drive.

      Is the image still exactly as it was made?

      This reads the image back and compares it with the SHA-256 saved beside it when it was made. The SSD is not needed. Use it before relying on the image, and once or twice a year with the copies. It changes nothing.

    5. 5

      See what the damage touched

      The program reads the image (or the recovered SSD itself, if no image was made) and works out which files and folders sit on the places ddrescue never read, and which files Windows cannot even list. It never writes to either. If the image is open read-only as a drive (with AIM Toolkit), it also checks itself against what Windows lists there.

    6. 6

      Copy everything off the SSD

      Every file and folder is copied straight off the image (or the SSD) into a folder on another drive: also the files Windows cannot list, and the data no folder names any more. Each copy's SHA-256 goes into the list of every file (rescue-log.csv), so it can be checked later. Choose an empty folder on a drive with room for everything, such as SPARE\WORK.

    7. 7

      Check every copied file

      Every file’s structure is read to find damage that looks fine on screen: a photo cut short, a block of zeros where the drive could not be read. With the results of step 5, a file the drive lost data from is marked NEVER_READ even when it looks fine.

      Are the copies still exactly what came off the SSD?

      Every copy's SHA-256 was written into rescue-log.csv as it was made. This reads every copy back and compares, then adds it all up in a safety check: the files step 5 found on the SSD, the files in the list of copies, and the files here now. Use it after every phase of the checklist, after a power cut, before the copies go anywhere, and once or twice a year after that. It changes nothing.

    8. 8

      Repair the damaged files: isolate, repair, put back

      The copies in WORK stay as they are. The damaged ones are copied into a REPAIR folder beside WORK, sorted by what can repair them, each with a number in its name (like [R0012]) that says exactly where it belongs. Repaired, they go back to exactly that place, and the damaged originals are kept in REPAIR\originals. Nothing is ever taken out of a package (a Photos library, an app, a Pages document): what is damaged inside one goes back to the same place inside it.

      Each folder in REPAIR\to-repair is named after what repairs its files. Repair those copies only, and save each repaired file anywhere in REPAIR\repaired, keeping its number in its name (IMG_0003 [R0012]_repaired.JPG is fine), in the same format as the original. What can't take the original's place (a TIFF of a damaged RAW photo, what 7-Zip takes out of a damaged archive) goes in REPAIR\salvaged instead. REPAIR\READ ME.txt says more.
